# TOTP

Time-based One-Time Passwords for **machine-to-machine** authentication. Classic TOTP
(RFC 6238) emits six decimal digits because a human has to type them; these tokens are
scanned from QR codes, sent as HTTP header values or used as short-lived replacements for
static API keys — so the design space is larger: an arbitrary alphabet (Base62 by default),
a longer default length (12 characters, up to 255), a Unicode shared secret instead of a
Base32-encoded binary key, and a previous/current/next token triple for a ±1-slot
acceptance window. HMAC-SHA256 by default; SHA-384 and SHA-512 on request.

> **The token format is frozen and independently specified.** The TypeScript implementation
> [TOTP.ts](https://github.com/OpenChargingCloud/TOTP.ts) derives byte-identical tokens, and
> both implementations are held to one set of canonical test vectors by a sibling
> repository, [TOTPConformanceTests](https://github.com/OpenChargingCloud/TOTPConformanceTests) —
> the written specification, the vectors (generated by an independent third implementation),
> and a harness per implementation. Two deliberate quirks of the byte-to-character mapping
> — a modulo bias for alphabet sizes that do not divide 256, and the hash being read as a
> ring buffer — are part of that frozen format and must not be "fixed" here; the
> specification documents them with numbers.

The format was developed for **OCPP v2.1**: use case C25 *"Ad hoc payment via a QR code"*
specifies it as *"TOTP algorithm, version 1"* — dynamic QR codes on a charging station
display, validated by the CSMS against a shared secret. OCPP v1 is exactly the
HMAC-SHA256/Base62 profile of what this folder implements.

## Layout

| File | Contents |
|---|---|
| `TOTP.cs` | `TOTPGenerator`: token derivation, previous/current/next triples, URL templates, TLS v1.3 channel binding |
| `TOTPConfig.cs` | A TOTP configuration as an immutable object with a JSON round-trip (`sharedSecret`, `validityTime`, `length`, `alphabet`, `useTLSExporterMaterial`, `hashAlgorithm`) |
| `TOTPHashAlgorithm.cs` | `sha256` / `sha384` / `sha512`, lenient parsing (`"SHA-256"`, `"HMAC_SHA512"`, …), canonical spellings |
| `TOTPHTTPHeader.cs` | The HTTP header carrier: a raw TOTP, or one bound to the TLS session |

## Using it

### Generating

```csharp
using org.GraphDefined.Vanaheimr.Hermod;

// All defaults: 30s validity, 12 characters, Base62, HMAC-SHA256.
var (previous, current, next, remainingTime, endTime)
    = TOTPGenerator.GenerateTOTPs("secure!Charging!");

// Everything explicit: 60s validity, 16 characters, Base32, HMAC-SHA512.
var (p, c, n, rem, end)
    = TOTPGenerator.GenerateTOTPs(
          "secure!Charging!",
          TimeSpan.FromSeconds(60),
          16,
          "ABCDEFGHIJKLMNOPQRSTUVWXYZ234567",
          HashAlgorithm: TOTPHashAlgorithm.SHA512
      );
```

`remainingTime` says when `current` expires — re-render your QR code then.

### Verifying

Compute the same triple and accept a presented token iff it equals one of the three; that
tolerates one slot of clock skew plus transmission delay in either direction. Compare
constant-time, remember accepted tokens for the lifetime of their slot where replay
matters, and never widen the window — increase the validity time instead.

### QR code / URL templates

`GenerateURL` fills a URL template, e.g. for OCPP-style dynamic QR codes:

```csharp
var (url, remaining, _) = TOTPGenerator.GenerateURL(
                              URL.Parse("https://qr.example.com/CS1000/1/{TOTP}/v1"),
                              "secure!Charging!"
                          );
// https://qr.example.com/CS1000/1/aHicux89zt2K/v1  — for the next ≤30 seconds
```

Further template parameters (`{evseId}`, `{maxEnergy}`, `{maxCost}`, …) are documented on
`ProcessURLTemplate`.

### TLS v1.3 channel binding

When both ends share a TLS v1.3 session, the token can be bound to it: exporter material
(RFC 8446 §7.5, label `TOTPGenerator.TLSExporterLabel`, empty context, 32 bytes) keys a
second HMAC over the first digest. A captured or logged token is then useless outside that
one TLS session.

```csharp
var (_, bound, _, _, _) = TOTPGenerator.GenerateTOTPs(
                              "secure!Charging!",
                              TLSExporterMaterial: tlsExporterMaterial
                          );
```

This extension is Hermod-only: TOTP.ts does not implement it, and it does not apply where
the token travels via a third party (as in the QR code flow).

## Input validation

Shared secret: at least 16 characters after trimming, no whitespace, keyed as raw UTF-8
without Unicode normalization. Token length: 4…255 — but positions beyond the hash length
(32/48/64 bytes) repeat, so longer buys nothing. Alphabet: at least 4 unique
non-whitespace characters; sizes that divide 256 (16/32/64) have zero modulo bias.
Validity time: a positive integer number of seconds. Timestamps: none before the Unix
epoch. Violations throw with the same error messages TOTP.ts uses — the conformance suite
holds both sides to them.

Secrets are symmetric keys: generate them randomly with at least 128 bits of entropy
(22+ random Base62 characters), never from passphrases.
